CEABOT RASPBERRY PI BOOT SERVICES - REINSTALL INSTRUCTIONS
=========================================================

Purpose
-------
These services start the Orbbec Gemini 330 ROS 2 driver and the CEAbot HTTP
capture server automatically at boot. A desktop session or automatic user
login is not required.

Assumptions
-----------
- Ubuntu user: thiwa
- ROS distribution: Jazzy
- Project: /home/thiwa/CEAbot_Rpi
- Capture server: /home/thiwa/CEAbot_Rpi/rpi_orbbec_capture_server.py
- Pi Ethernet address: 10.20.0.200
- Orbbec ROS package and Gemini 330 launch file are installed.

Files included in this folder
-----------------------------
- orbbec-camera.service
- ceabot-capture.service
- ceabot-capture.env.example
- ros_jazzy.bash
- REINSTALL_INSTRUCTIONS.txt

Automatically enable ROS commands in every terminal
---------------------------------------------------
The ros_jazzy.bash file sources ROS 2 Jazzy and, when present, the Orbbec
workspace overlay at /home/thiwa/orbbec_ws/install/setup.bash.

Add it to the shell startup file once:

echo 'source /home/thiwa/CEAbot_Rpi/systemd_boot_setup/ros_jazzy.bash' >> ~/.bashrc

Apply it to the current terminal without logging out:

source ~/.bashrc

Verify it:

echo $ROS_DISTRO
ros2 --help

ROS commands will then be available automatically in every newly opened Bash
terminal. This shell setup is for interactive terminals; the systemd service
files source ROS independently and do not depend on ~/.bashrc.

1. Verify ROS and the camera launch file
----------------------------------------
source /opt/ros/jazzy/setup.bash
ros2 pkg prefix orbbec_camera
ros2 launch orbbec_camera gemini_330_series.launch.py --show-args

2. Copy the service files
-------------------------
cd /home/thiwa/CEAbot_Rpi/systemd_boot_setup
sudo cp orbbec-camera.service /etc/systemd/system/
sudo cp ceabot-capture.service /etc/systemd/system/
sudo chmod 644 /etc/systemd/system/orbbec-camera.service
sudo chmod 644 /etc/systemd/system/ceabot-capture.service

Do not copy files directly into multi-user.target.wants. The systemctl enable
command below creates the correct symbolic links there.

3. Create the private authentication-token file
------------------------------------------------
Generate a token:

openssl rand -hex 32

Create the file:

sudo nano /etc/ceabot-capture.env

Add this line, replacing the example value with the generated token:

CEABOT_CAPTURE_TOKEN=replace_with_the_generated_token

Protect the file:

sudo chown root:root /etc/ceabot-capture.env
sudo chmod 600 /etc/ceabot-capture.env

Configure the Jetson to use exactly the same token. The example file in this
folder intentionally does not contain the real secret.

4. Configure the Ethernet address
---------------------------------
The capture server binds to 10.20.0.200. Confirm that this address is assigned
to eth0 before expecting the server to start:

ip -brief address show eth0

If the Pi uses a different address, edit ceabot-capture.service and change the
value after --bind before copying it into /etc/systemd/system.

For testing on all configured network interfaces, --bind may be changed to
0.0.0.0. Keep the firewall and bearer-token security in mind when doing this.

5. Enable and start both services
---------------------------------
sudo systemctl daemon-reload
sudo systemctl enable --now orbbec-camera.service
sudo systemctl enable --now ceabot-capture.service

6. Check status and logs
------------------------
systemctl status orbbec-camera.service
systemctl status ceabot-capture.service

journalctl -u orbbec-camera.service -f
journalctl -u ceabot-capture.service -f

Test the HTTP server locally:

curl http://10.20.0.200:8080/health

7. Restart after editing a service
----------------------------------
After changing either service file in this repository, install the edited file,
reload systemd, restart the service, and check its logs.

For the Gemini camera service:

cd /home/thiwa/CEAbot_Rpi/systemd_boot_setup
sudo cp orbbec-camera.service /etc/systemd/system/
sudo chmod 644 /etc/systemd/system/orbbec-camera.service
sudo systemctl daemon-reload
sudo systemctl restart orbbec-camera.service
journalctl -u orbbec-camera.service -f

For the capture server service:

sudo cp ceabot-capture.service /etc/systemd/system/
sudo chmod 644 /etc/systemd/system/ceabot-capture.service
sudo systemctl daemon-reload
sudo systemctl restart ceabot-capture.service
journalctl -u ceabot-capture.service -f

8. Disable the automatic services if needed
--------------------------------------------
sudo systemctl disable --now ceabot-capture.service
sudo systemctl disable --now orbbec-camera.service

Useful boot setting for headless/server mode
--------------------------------------------
Boot without the desktop:

sudo systemctl set-default multi-user.target

Restore graphical boot later:

sudo systemctl set-default graphical.target

Important notes
---------------
- Installed service files belong in /etc/systemd/system.
- The multi-user.target.wants directory contains links created by systemctl.
- Keep the real CEABOT_CAPTURE_TOKEN outside this project and out of Git.
- Both services use Restart=on-failure and retry five seconds after a crash.
- The capture service can start before camera frames arrive; capture requests
  will work after the camera begins publishing synchronized RGB/depth images.
