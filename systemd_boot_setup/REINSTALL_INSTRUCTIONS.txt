CEABOT RASPBERRY PI BOOT SERVICES - REINSTALL INSTRUCTIONS
=========================================================

Purpose
-------
These services start the Orbbec Gemini 305 ROS 2 driver and the CEAbot HTTP
capture server automatically at boot. A desktop session or automatic user
login is not required.

Assumptions
-----------
- Ubuntu user: thiwa
- ROS distribution: Jazzy
- Project: /home/thiwa/CEAbot_Rpi
- Capture server: /home/thiwa/CEAbot_Rpi/rpi_orbbec_capture_server.py
- Pi Ethernet address: 10.20.0.200
- Orbbec ROS wrapper/SDK 2.8.6 or newer is installed from v2-main.
- Gemini 305 firmware 1.0.70 is used with gemini_301_series.launch.py.

Files included in this folder
-----------------------------
- orbbec-camera.service
- ceabot-capture.service
- ceabot-expansion-network.service (legacy; NetworkManager now owns eth0)
- ceabot-capture.env.example
- ros_jazzy.bash
- REINSTALL_INSTRUCTIONS.txt

Automatically enable ROS commands in every terminal
---------------------------------------------------
The ros_jazzy.bash file sources ROS 2 Jazzy and, when present, the Orbbec
workspace overlay at /home/thiwa/orbbec_ws/install/setup.bash.

Add it to the shell startup file once:

echo 'source /home/thiwa/CEAbot_Rpi/systemd_boot_setup/ros_jazzy.bash' >> ~/.bashrc

Apply it to the current terminal without logging out:

source ~/.bashrc

Verify it:

echo $ROS_DISTRO
ros2 --help

ROS commands will then be available automatically in every newly opened Bash
terminal. This shell setup is for interactive terminals; the systemd service
files source ROS independently and do not depend on ~/.bashrc.

1. Install or upgrade the Orbbec SDK for Gemini 305
---------------------------------------------------
Gemini 305 firmware 1.0.70 requires wrapper/SDK 2.8.6 or newer. Stop the
services and disconnect the camera before building:

sudo systemctl stop ceabot-capture.service orbbec-camera.service
pkill -f component_container || true

When upgrading the old 2.7.6 workspace, retain it as a backup:

cd /home/thiwa
mv orbbec_ws orbbec_ws_2_7_6_backup
mkdir -p orbbec_ws/src

source /opt/ros/jazzy/setup.bash
sudo apt update
sudo apt install -y git libgflags-dev nlohmann-json3-dev libdw-dev libssl-dev \
  mesa-utils libgl1 libgoogle-glog-dev ros-jazzy-image-transport \
  ros-jazzy-image-transport-plugins ros-jazzy-compressed-image-transport \
  ros-jazzy-image-publisher ros-jazzy-camera-info-manager \
  ros-jazzy-diagnostic-updater ros-jazzy-diagnostic-msgs \
  ros-jazzy-statistics-msgs ros-jazzy-xacro ros-jazzy-backward-ros

cd /home/thiwa/orbbec_ws/src
git clone --branch v2-main --single-branch \
  https://github.com/orbbec/OrbbecSDK_ROS2.git
cd /home/thiwa/orbbec_ws
colcon build --event-handlers console_direct+ \
  --cmake-args -DCMAKE_BUILD_TYPE=Release

cd /home/thiwa/orbbec_ws/src/OrbbecSDK_ROS2/orbbec_camera/scripts
sudo bash install_udev_rules.sh
sudo udevadm control --reload-rules
sudo udevadm trigger

Power-cycle the Pi and camera after installing the rules.

2. Verify ROS and the camera launch file
----------------------------------------
source /opt/ros/jazzy/setup.bash
source /home/thiwa/orbbec_ws/install/setup.bash
ros2 pkg prefix orbbec_camera
ros2 pkg xml orbbec_camera | grep '<version>'
ros2 run orbbec_camera list_devices_node
ros2 launch orbbec_camera gemini_301_series.launch.py --show-args

3. Copy the service files
-------------------------
Stop the dependent services before replacing their unit files:

sudo systemctl stop ceabot-capture.service
sudo systemctl stop orbbec-camera.service

cd /home/thiwa/CEAbot_Rpi/systemd_boot_setup
sudo cp orbbec-camera.service /etc/systemd/system/
sudo cp ceabot-capture.service /etc/systemd/system/
sudo chmod 644 /etc/systemd/system/orbbec-camera.service
sudo chmod 644 /etc/systemd/system/ceabot-capture.service

Do not copy files directly into multi-user.target.wants. The systemctl enable
command below creates the correct symbolic links there.

4. Configure the same private token on the Pi and Jetson
---------------------------------------------------------
Generate one token on the Pi:

openssl rand -hex 32

Copy the generated value somewhere private temporarily. On the Pi, create the
environment file used by ceabot-capture.service:

sudo nano /etc/ceabot-capture.env

Add this line, replacing the placeholder with the generated value:

CEABOT_CAPTURE_TOKEN=replace_with_the_generated_token

Protect the Pi file and restart the capture server if it is already running:

sudo chown root:root /etc/ceabot-capture.env
sudo chmod 600 /etc/ceabot-capture.env
sudo systemctl try-restart ceabot-capture.service

On the Jetson, store the exact same token in a user-owned private file:

mkdir -p /home/thiwa/.config/ceabot
chmod 700 /home/thiwa/.config/ceabot
nano /home/thiwa/.config/ceabot/capture.env

Add the same line and value used on the Pi:

CEABOT_CAPTURE_TOKEN=replace_with_the_same_generated_token

Protect the Jetson file:

chmod 600 /home/thiwa/.config/ceabot/capture.env

Before starting the main ROS launch in each new Jetson shell, export the token:

set -a
source /home/thiwa/.config/ceabot/capture.env
set +a
source /home/thiwa/CEAbot/install/setup.bash
ros2 launch bench_robot full_robot.launch.py

The main launch passes CEABOT_CAPTURE_TOKEN to remote_orbbec_capture. The two
files persist across reboot and their token values do not change automatically.
After reboot, the Pi service loads its file automatically. A manually started
Jetson launch still needs the source commands above in each new shell.

Do not put the real token in ceabot-capture.env.example, a launch file, source
code, commands.txt, shell history, or Git. If the token is changed, update both
devices so their values continue to match.

Test authentication from the Jetson after loading the environment file:

curl -H "Authorization: Bearer $CEABOT_CAPTURE_TOKEN" \
  http://10.20.0.200:8080/health

5. Persist the Ethernet addresses and routes with NetworkManager
----------------------------------------------------------------
NetworkManager already owns these Ethernet interfaces. Configure its existing
profiles instead of enabling the legacy oneshot network services; otherwise
NetworkManager can remove addresses and routes after the services exit.

On the Pi, the existing connection is named netplan-eth0. Configure the static
address, return route, and Kinova expansion-port link settings:

sudo nmcli connection modify netplan-eth0 \
  ipv4.method manual \
  ipv4.addresses 10.20.0.200/24 \
  ipv4.gateway "" \
  ipv4.routes "192.168.1.0/24 10.20.0.1" \
  ipv4.never-default yes \
  ipv6.method link-local \
  802-3-ethernet.auto-negotiate no \
  802-3-ethernet.speed 100 \
  802-3-ethernet.duplex full \
  connection.autoconnect yes

sudo nmcli connection up netplan-eth0

Verify the Pi before continuing:

ip -brief address show eth0
ip route get 192.168.1.2
ping -c 4 10.20.0.1

On the Jetson, find the NetworkManager connection attached to enP1p1s0:

nmcli device status
nmcli -g GENERAL.CONNECTION device show enP1p1s0

If it reports a connection name such as "Wired connection 1", substitute that
exact name in these commands:

sudo nmcli connection modify "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses 192.168.1.2/24 \
  ipv4.gateway "" \
  ipv4.routes "10.20.0.0/24 192.168.1.10" \
  ipv4.never-default yes \
  ipv6.method link-local \
  connection.autoconnect yes

sudo nmcli connection up "Wired connection 1"

If GENERAL.CONNECTION reports -- instead, create and activate a connection:

sudo nmcli connection add \
  type ethernet \
  ifname enP1p1s0 \
  con-name ceabot-kinova \
  ipv4.method manual \
  ipv4.addresses 192.168.1.2/24 \
  ipv4.routes "10.20.0.0/24 192.168.1.10" \
  ipv4.never-default yes \
  ipv6.method link-local \
  connection.autoconnect yes

sudo nmcli connection up ceabot-kinova

Verify the Jetson:

ip -brief address show enP1p1s0
ip route get 10.20.0.200
ping -c 4 192.168.1.10
ping -c 4 10.20.0.200

Reboot both devices and repeat the address, route, and ping checks. Only after
the NetworkManager settings survive reboot, disable any previously installed
legacy network service on the corresponding device:

# Run on the Pi, if this legacy service was installed:
sudo systemctl disable --now ceabot-expansion-network.service

# Run on the Jetson, if this legacy service was installed:
sudo systemctl disable --now jetson-ceabot-rpi-route.service

The Pi should retain 10.20.0.200/24 and the Jetson should retain
192.168.1.2/24. These profiles also persist their cross-network routes.

If the Pi uses a different address, edit ceabot-capture.service and change the
value after --bind before copying it into /etc/systemd/system.

For testing on all configured network interfaces, --bind may be changed to
0.0.0.0. Keep the firewall and bearer-token security in mind when doing this.

6. Enable and start all services
---------------------------------
sudo systemctl daemon-reload
sudo systemctl reset-failed orbbec-camera.service ceabot-capture.service
sudo systemctl enable orbbec-camera.service ceabot-capture.service
sudo systemctl start orbbec-camera.service
sudo systemctl start ceabot-capture.service

7. Check status and logs
------------------------
systemctl status orbbec-camera.service
systemctl status ceabot-capture.service

journalctl -u orbbec-camera.service -f
journalctl -u ceabot-capture.service -f

Test the authenticated HTTP server locally on the Pi:

sudo bash -c 'set -a; source /etc/ceabot-capture.env; curl -H "Authorization: Bearer $CEABOT_CAPTURE_TOKEN" http://10.20.0.200:8080/health'

8. Restart after editing a service
----------------------------------
After changing a service file in this repository, stop its dependents, install
the edited file, reload systemd, start it again, and check its logs.

For the Gemini camera service:

cd /home/thiwa/CEAbot_Rpi/systemd_boot_setup
sudo systemctl stop ceabot-capture.service
sudo systemctl stop orbbec-camera.service
sudo cp orbbec-camera.service /etc/systemd/system/
sudo chmod 644 /etc/systemd/system/orbbec-camera.service
sudo systemctl daemon-reload
sudo systemctl start orbbec-camera.service
sudo systemctl start ceabot-capture.service
journalctl -u orbbec-camera.service -f

For the capture server service:

sudo systemctl stop ceabot-capture.service
sudo cp ceabot-capture.service /etc/systemd/system/
sudo chmod 644 /etc/systemd/system/ceabot-capture.service
sudo systemctl daemon-reload
sudo systemctl start ceabot-capture.service
journalctl -u ceabot-capture.service -f

9. Disable the automatic services if needed
--------------------------------------------
sudo systemctl disable --now ceabot-capture.service
sudo systemctl disable --now orbbec-camera.service

Useful boot setting for headless/server mode
--------------------------------------------
Boot without the desktop:

sudo systemctl set-default multi-user.target

Restore graphical boot later:

sudo systemctl set-default graphical.target

Important notes
---------------
- Installed service files belong in /etc/systemd/system.
- The multi-user.target.wants directory contains links created by systemctl.
- Keep the real CEABOT_CAPTURE_TOKEN outside this project and out of Git.
- Both services use Restart=on-failure and retry five seconds after a crash.
- The capture service can start before camera frames arrive; capture requests
  will work after the camera begins publishing synchronized RGB/depth images.
